# 治理升级业务使用文档

> 本文档面向存储区人员，介绍如何使用链上参数治理系统完成参数修改提案提交、投票和执行的全流程。

---

## 一、概述

参数治理系统（ParameterRegistry）是一个部署在 PunkChain 上的智能合约，用于管理链上各类参数的修改。参数修改不能随意进行，必须经过 **提案 → 投票 → 执行** 的治理流程，确保变更得到足够多的治理代币持有者认可。

### 1.1 核心概念

| 概念 | 说明 |
|------|------|
| **治理代币（GOV）** | **治理凭证，持有治理代币才能发起提案，参与投票，投票权重与持币数量成正比** |
| **参数级别** | 参数按重要性分为三级，级别越高所需赞成比例越高 |
| **提案** | 对某个已注册参数发起修改请求，包含新值和修改说明 |
| **投票** | 治理代币持有者在投票期内对提案投赞成或反对票 |
| **执行** | 投票通过后，调用合约执行参数变更 |

### 1.2 参数级别与通过阈值

| 级别 | 枚举值 | 含义 | 通过阈值 |
|:-----|:-------|------|----------|
| APPLICATION（应用级） | 0 | 应用层参数，影响范围较小 | 赞成票 ≥ 66.67%（2/3） |
| SYSTEM（系统级） | 1 | 系统层参数，影响范围中等 | 赞成票 ≥ 75%（3/4） |
| INFRASTRUCTURE（底层级） | 2 | 基础设施参数，影响范围最大 | 赞成票 ≥ 80%（4/5） |

### 1.3 时间参数

| 参数 | 值 | 说明 |
|------|-----|------|
| VOTING_DELAY | 60 秒 | 提案创建后到投票开始的等待时间 |
| VOTING_PERIOD | 120 秒 | 投票窗口持续时间 |

> **注意**：当前为测试阶段，时间参数较短。正式上线后将调整为更长的时间窗口。

### 4.4 步骤 2：注册参数并分发代币（02_register_params.js）

**作用**：
1. 在 ParameterRegistry 合约中注册存储区的三个参数（maxFileSize、replicationFactor、shardSize）
2. 为 deployer 铸造 50 GOV 治理代币，为 5 个投票者各铸造 100 GOV 治理代币

**何时运行**：合约部署后运行一次。若参数已注册，脚本会自动跳过。

```bash
npx hardhat run scripts/upgrade_process/02_register_params.js --network punkchain

**输出示例**：

```

- replicationFactor registered
- shardSize registered

**关键说明**：
- 参数使用 `category = "storage"` 进行分类
- 参数 ID 通过 `keccak256(abi.encodePacked(name, category))` 生成

### 4.5 步骤 3：发起提案（03_propose.js）⭐ 重点

**作用**：对已注册的参数发起修改提案。当前脚本示例为将 `replicationFactor`（副本数）从当前值修改为 20。

**何时运行**：每次需要修改参数时运行。

```bash
npx hardhat run scripts/upgrade_process/03_propose.js --network punkchain
```

**输出示例**：

```
Proposal created: {
  proposalId: '9',
  parameterId: '0x71c59234b929e153cdd3eb30b70fb55ad7a5fa8436dac87a5273944150557162',
  newValue: 20
}
Saved to: .../state.json
```

**产出文件**：`scripts/upgrade_process/state.json`

```json
{
  "proposalId": "9",
  "parameterId": "0x71c59234...",
  "newValue": 20
}
```

**如何修改提案内容**：

编辑 `03_propose.js` 中的以下部分：

```javascript
// 修改目标参数名
const targetParamName = "replicationFactor";  // 可改为 "maxFileSize" 或 "shardSize"

// 修改新值
const newValue = 20;  // 修改为你期望的新值

// 修改提案说明
"将存储副本数从 10 增加到 20，提高数据可靠性"  // 修改为本次提案的说明
```

**支持修改的参数列表**：

| targetParamName | 含义 | 值类型 |
|-----------------|------|--------|
| `"maxFileSize"` | 最大文件大小（字节） | uint256 |
| `"replicationFactor"` | 数据副本数 | uint256 |
| `"shardSize"` | 分片大小（字节） | uint256 |

### 4.6 步骤 4：投票（04_vote.js）⭐ 重点

**作用**：等待投票延迟期过后，5 个投票者对提案进行投票。

**何时运行**：步骤 3 发起提案后运行。脚本会自动等待投票延迟期（60 秒）。

```bash
npx hardhat run scripts/upgrade_process/04_vote.js --network punkchain
```

**输出示例**：
```
Proposal details: [...]
Waiting for voting period...
   ⏳ 目标时间: 2025-02-13T...
   ⛏️ 触发挖矿交易，尝试更新区块时间...
- 投票者1: 赞成
- 投票者2: 赞成
- 投票者3: 赞成
- 投票者4: 赞成
- 投票者5: 反对
Voting done.
```

**投票机制说明**：
- 脚本中默认 voter1~4 投赞成票，voter5 投反对票（4 赞成 / 1 反对 = 80% 赞成率）
- 此赞成率满足所有三个级别的阈值要求
- 在 PunkChain 上，脚本会通过发送挖矿交易来推进区块时间，每 30 秒检查一次

**如何修改投票行为**：

编辑 `04_vote.js` 中的 `votes` 数组：

```javascript
const votes = [
  { voter: voter1, support: true,  label: "投票者1" },  // true = 赞成
  { voter: voter2, support: true,  label: "投票者2" },
  { voter: voter3, support: true,  label: "投票者3" },
  { voter: voter4, support: true,  label: "投票者4" },
  { voter: voter5, support: false, label: "投票者5" }   // false = 反对
];
```

### 4.7 步骤 5：执行提案（05_execute.js）⭐ 重点

**作用**：等待投票期结束后，检查提案是否通过，通过则执行参数变更。

**何时运行**：步骤 4 投票完成后运行。脚本会自动等待投票期结束（120 秒）。

```bash
npx hardhat run scripts/upgrade_process/05_execute.js --network punkchain
```

**输出示例**：
```
Waiting for voting to end...
   ⏳ 目标时间: 2025-02-13T...
   ⛏️ 触发挖矿交易，尝试更新区块时间...
Proposal executed.
```

**提案状态说明**：

| 状态 | 值 | 说明 |
|------|-----|------|
| Pending | 0 | 等待投票开始 |
| Active | 1 | 投票进行中 |
| Succeeded | 2 | 投票通过，可执行 |
| Defeated | 3 | 投票未通过 |
| Executed | 4 | 已执行 |
| Canceled | 5 | 已取消 |

> 只有状态为 **Succeeded（2）** 的提案才能被执行。如果提案未通过，脚本会输出当前状态并退出。

## 五、完整操作指南（快速上手）

### 5.1 首次部署（仅执行一次）

```bash
# 1. 安装依赖（如尚未安装）
npm install

# 2. 为账户充值 gas
npx hardhat run scripts/fund-metamask-accounts.js --network punkchain

# 3. 部署合约
npx hardhat run scripts/upgrade_process/01_deploy.js --network punkchain

# 4. 注册参数 & 分发治理代币
npx hardhat run scripts/upgrade_process/02_register_params.js --network punkchain
```

### 5.2 每次发起参数修改（可反复执行）

```bash
# 1. 编辑 03_propose.js，设置要修改的参数和新值
#    （修改 targetParamName、newValue、提案描述）

# 2. 发起提案
npx hardhat run scripts/upgrade_process/03_propose.js --network punkchain

# 3. 投票（自动等待投票延迟期，约 60 秒后开始投票）
npx hardhat run scripts/upgrade_process/04_vote.js --network punkchain

# 4. 执行提案（自动等待投票期结束，约 120 秒）
npx hardhat run scripts/upgrade_process/05_execute.js --network punkchain

# 5. 查询已执行的提案（可选，验证结果）
npx hardhat run scripts/print-proposal-executed.js --network punkchain
```

> **时间预估**：从发起提案到执行完成，整个流程约需 **3~5 分钟**（含等待时间）。

## 七、常见问题

### Q1：提案执行失败，提示 "Proposal not succeeded"？

**原因**：赞成票比例未达到该参数级别的阈值要求。

**解决**：
- 检查投票者数量和投票意向是否满足阈值
- APPLICATION 级参数需 ≥ 66.67% 赞成
- SYSTEM 级参数需 ≥ 75% 赞成
- INFRASTRUCTURE 级参数需 ≥ 80% 赞成

### Q2：脚本等待时间过长，一直在 "等待区块时间更新"？

**原因**：PunkChain 不支持 `evm_increaseTime`，需要通过实际交易推进区块时间。

**解决**：正常现象，脚本每 30 秒发送一笔挖矿交易来推进时间。如果超过最大等待时间（投票阶段 300 秒，执行阶段 180 秒），脚本会自动退出，请稍后重新运行。

### Q3：出现 "insufficient funds" 错误？

**原因**：操作账户 ETH 余额不足以支付 gas 费用。

**解决**：运行资金充值脚本：
```bash
npx hardhat run scripts/fund-metamask-accounts.js --network punkchain
```

### Q4：出现 "Parameter not registered" 错误？

**原因**：尝试修改的参数尚未注册，或参数名称拼写错误。

**解决**：
1. 确认参数已通过 `02_register_params.js` 注册
2. 检查 `03_propose.js` 中的 `targetParamName` 拼写是否与注册时一致

### Q5：如何注册新的存储参数？

编辑 `02_register_params.js`，在 `storageParams` 数组中添加新参数：

```javascript
const storageParams = [
  // 已有参数...
  { name: "myNewParam", level: ParameterLevel.APPLICATION, initialValue: 100 }
];
```

然后重新运行注册脚本（已注册的参数会自动跳过）。

### Q6：如何查看某个参数的当前值？

可通过合约方法 `parameters(parameterId)` 查询。查询代码如下：

```javascript
const { ethers } = require("hardhat");
const fs = require("fs");
const path = require("path");

const DEPLOYED_PATH = path.join(__dirname, "upgrade_process", "deployed.json");
const deployed = JSON.parse(fs.readFileSync(DEPLOYED_PATH, "utf8"));

function generateParameterId(name, category) {
  return ethers.keccak256(
    ethers.solidityPacked(["string", "bytes32"], [name, category])
  );
}

async function main() {
    const provider = ethers.provider;
    const deployer = new ethers.Wallet(
        "eeefa7075d12e965851eef8e2622377d480f8b9c99c30cb615cf222b699b491f",
        provider
    );
    const paramRegistry = await ethers.getContractAt("ParameterRegistry", deployed.paramRegistry, deployer);

    const CATEGORY_STORAGE = ethers.encodeBytes32String("storage");
    const param = { name: "replicationFactor", level: 1, initialValue: 3 };
    const paramId = generateParameterId(param.name, CATEGORY_STORAGE);

    const info = await paramRegistry.parameters(paramId);

    console.log("Parameter Info:", info);
}

main()
  .then(() => process.exit(0))
  .catch((error) => {
    console.error("执行失败:", error);
    process.exit(1);
  });
```

## 八、注意事项

1. **网络切换**：所有命令需加 `--network punkchain` 参数才能在 PunkChain 上执行；不加则默认在本地 Hardhat 网络运行
2. **顺序执行**：步骤 3→4→5 必须**按顺序依次执行**，不可跳步或并行
3. **state.json**：每次发起新提案会覆盖 `state.json`，请确保上一个提案已完成或记录了其提案 ID
4. **时间等待**：PunkChain 上需要等待真实时间，期间脚本会自动发送交易推进区块时间
5. **重复执行**：已执行的提案不能再次执行；已投票的地址不能重复投票
